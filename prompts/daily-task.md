# 예약 작업 프롬프트 — Daily Stock Study 오늘의 강의

> 이 파일은 Claude 예약 작업(평일 19:43 KST, `CRON_TZ=Asia/Seoul 43 19 * * 1-5`)에 그대로 넣는 지시문입니다.
> 예약 작업을 만들 때 아래 `{{받는 사람}}` 자리에 본인 메일 주소를 적습니다.
> **메일 주소는 이 저장소에 절대 커밋하지 않습니다**(예약 작업 설정에만 저장).

---

당신은 「Daily Stock Study」의 오늘 강의를 만드는 작업을 합니다.
저장소: `qkqh6898-woohak/DailyStock` (쓰기 권한 필요, 기본 브랜치 `main`)
알림 메일 받는 사람: `{{받는 사람}}`

이 앱은 **교육용**입니다. 특정 종목의 매수·매도 권유, 목표 주가, 수익 보장처럼 읽히는 표현을 절대 쓰지 않습니다.
검증 도구가 "매수 추천", "목표가", "지금 사야", "무조건 오른다" 같은 표현을 찾으면 실패합니다.

## 1. 오늘 만들 강의 확인

1. 저장소를 클론하고 저장소 폴더로 들어갑니다.
2. 아래를 실행해 오늘 강의 정보를 확인합니다(날짜는 한국 시간 기준으로 자동 계산).
   ```
   node tools/next-lesson.mjs
   ```
   - `already_exists` 가 true 이고 `existing_is_sample` 이 false 이면 오늘 강의는 이미 있습니다. 아무것도 바꾸지 말고 끝냅니다(메일도 보내지 않음).
   - `lesson_no`(강의 번호), `track`, `title`, `goal`, `key_terms`, `key_terms_to_define`(사전에 아직 없어 이번에 정의할 용어), `glossary_ids`(이미 있는 용어), `round`(2 이상이면 2회차 심화)를 확인합니다.
   - 강의 번호는 "샘플을 뺀 가장 최근 강의 + 1" 입니다. 어제 실패했다면 같은 번호가 다시 나옵니다. 번호를 직접 바꾸지 마세요.
3. 형식은 `plan.md` 3장과 샘플 강의 `lessons/2026/11/2026-11-11.json` 을 참고합니다.

## 2. 사례 고르기와 숫자 모으기

1. 웹 검색으로 오늘(장 마감 기준) 이 개념을 설명하기 좋은 국내 또는 미국 시장 뉴스 1개를 고릅니다.
   - 배터리·EV 관련 사례가 적합하면 우선합니다. 국내 70% · 미국 30% 정도로 섞습니다.
   - 신뢰도 높은 출처 2곳 이상을 확인합니다(공시·회사 발표·주요 언론 우선).
   - **T7(계좌·세금) 강의**는 반드시 최신 제도를 검색하고 국세청·금융위원회·기획재정부 등 공식 출처를 씁니다.
   - 오늘이 휴장일이거나 적당한 뉴스가 없으면 지난주 이슈로 "복습 사례"를 쓰고 `news_case.kind` 를 `"review"` 로 둡니다.
   - `round` 가 2 이상이면 같은 주제를 실제 기업 1곳을 깊게 분석하는 방식으로 씁니다.
2. 사례에 쓸 숫자마다 **출처 주소(https)와 기준일**을 기록합니다. 가능하면 두 출처로 교차 확인하고, 확인할 수 없는 숫자는 쓰지 않습니다.
3. 숫자를 계산해서 만든 값(비율·배수 등)은 `derived` 에 계산식을 적습니다(예: `"f0 / f1"`). 검증기가 다시 계산해 ±1% 안인지 확인합니다.

## 3. 강의 쓰기 — `lessons/YYYY/MM/YYYY-MM-DD.json`

뉴스 원문을 복사하지 말고, 사실만 바탕으로 직접 설명합니다.

- `schema: 1`, `date`(오늘), `lesson_no`, `track`, `title`(60자 이내), `disclaimer: true`
- `summary`: 한 줄 요약 정확히 3개
- `body`: 문단 3~7개, **한글 800~1,200자**, 초보자가 이해할 수 있게, 비유 1개 이상,
  장기 투자자(10년 이상) 관점의 시사점 한 문단
- **숫자 규칙**: 본문·요약·뉴스 설명에 아라비아 숫자를 직접 쓰지 않습니다. 모든 숫자는 `facts` 에 넣고 `{{f:번호}}` 로 참조합니다.
  - 예외(직접 써도 됨): 연도(2026년), 날짜·시각(11월 30일, 15시 30분), 분기(3분기), 강의 번호(21강),
    한두 자리 수 + 세는 말(3가지, 2개, 10년), 고유 이름(S&P500, 코스피200, NCM811).
  - 그 밖의 고유명사 숫자(예: 4680 배터리)는 강의 파일의 `allow_numbers: ["4680"]` 에 적습니다.
- `facts[]`: `id`(0부터), `label`, `value`(숫자, 콤마 없이), `unit`("원", "%", "배", "명" …), `asof`(YYYY-MM-DD, 강의 날짜보다 미래 불가), `source_url`(https)
  - 선택: `derived`(계산식), `change: true`(등락: ▲▼ 표시), `digits`(소수 자릿수), `note`
- 용어 표시: `[[용어id]]` 또는 `[[용어id|본문에 보일 말]]`. 용어 id 는 영문 소문자·숫자·하이픈.
  - 새 용어는 `terms[]` 에 추가: `id`, `ko`, `en`, `short`(40자 이내) 필수, `long`, `formula`, `example`, `related` 권장.
  - `key_terms_to_define` 의 용어는 반드시 `terms` 에 정의합니다. 이미 사전에 있는 용어(`glossary_ids`)는 다시 정의하지 않아도 됩니다.
- `formula`: 공식이 있으면 `{ "text": "PER = 주가 ÷ EPS", "terms": ["per", "eps"] }`
- `news_case`: `headline`, `explain`(문단 배열), `sources`(1개 이상, `{ name, url }`, https), 선택 `kind`("news" | "review"), `date`
- `english`: 실제 비즈니스·투자 대화에서 쓰는 영어 문장 2개 `{ en, ko }`
- `quiz`: 정확히 3문제 — `concept` · `calc` · `case` 각 1개, 보기 4개(서로 다르게), `answer`(0~3), `explain`
  - 계산 문제에는 `calc` 필수: `{ "vars": { "price": 50000, "eps": 4000 }, "expr": "price / eps", "template": "주가 {price}원, EPS {eps}원일 때 PER은?", "unit": "배", "digits": 1 }`
    - `expr` 은 사칙연산·괄호·거듭제곱(^)만 씁니다. 검증기가 계산해 정답 보기와 ±1% 일치를 확인합니다.
    - `template` 은 토요일 주간 퀴즈에서 앱이 숫자만 바꿔 새 문제를 만들 때 씁니다(모든 변수를 `{이름}` 으로 넣기).

## 4. 검증 (반드시 이 순서로)

```
node tools/merge-terms.mjs lessons/YYYY/MM/YYYY-MM-DD.json
node tools/build-index.mjs
node tools/validate.mjs lessons/YYYY/MM/YYYY-MM-DD.json
node tools/validate.mjs --all
node --test tests/*.test.mjs
```

- 실패하면 출력된 위치·이유(예: `body[1]: 숫자 "52,300"이 facts 참조 없이 쓰였습니다`)를 보고 고친 뒤 다시 검증합니다(최대 3회).
- 경고(⚠)는 실패가 아니지만, 본문 길이 경고는 가능하면 맞춥니다.
- 3회 안에 통과하지 못하면 **커밋하지 말고** 6-B 로 갑니다.

## 5. 저장

통과하면 아래 메시지로 `main` 에 커밋·푸시합니다.

```
content: YYYY-MM-DD 강의 N 추가
```

강의 파일, `lessons/index.json`, `glossary/terms.json` 만 바뀌어야 합니다. 앱 코드(`js/`, `css/`, `sw.js` 등)는 건드리지 않습니다.
